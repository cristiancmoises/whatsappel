# pqenv and Org audit — 2026-09-09

This is a source review and automated regression audit performed during the
whatsappel improvement work. It is not an independent third-party security audit,
formal protocol proof, or production certification. Severity labels below are
qualitative review judgments, not CVSS scores.

## Scope and evidence

Reviewed all Rust sources and manifests in `pqenv/`, `whatsapp-org.el`, the setup
script, systemd service, and optional contrib files. Changes in this component
cover Rust and Org; repository-level findings belong to the main project audit.
The default x86_64 Linux build was exercised with Rust 1.93.0 and Emacs 29.3.
No WhatsApp account, live Wuzapi instance, production deployment, AArch64 machine,
SIMD-specific build, or cross-platform environment was used.

Baseline: `cargo test --locked` passed all 27 pre-existing Rust tests. After the
changes, all **39 Rust tests** pass: 31 library/property tests, five storage/CLI
unit tests, and three real CLI integration tests. `cargo clippy --locked
--all-targets -- -D warnings` and `cargo fmt --check` pass. Five Org ERT tests pass,
including real capture-template expansion. Org byte compilation passed without
warnings, and the final source was loaded and tested by ERT. Exact commands are listed in the component README and
repository Makefile.

## Corrected findings

| Finding | Severity | Evidence and correction |
|---|---|---|
| Capture can execute received Lisp or insert local files | High | `whatsapp-org--esc` used `%%`, while Org capture escapes placeholders with backslashes. Received `%(...)` or `%[path]` remained active. Correct escaping now accounts for preceding backslashes and strips incoming text properties. Regression tests expand actual capture templates and verify no code execution or substitution. |
| Captured messages can escape their block | Medium | An incoming block terminator or heading could become active Org structure. Capture now uses an example block with Org's own comma escaping and single-line headings/properties; link text uses Org's link builder. Tests verify exactly one headline/example block and no source block. |
| Sending Org can execute code before confirmation | High | Export happened before the send confirmation, with Babel and evaluated macros enabled and INCLUDE expansion active. This export now suppresses Babel, macro expansion, INCLUDE expansion and BIND options. Tests verify Babel/eval macros do not run and local INCLUDE content is absent. User-defined Org hooks/backends remain trusted local configuration. |
| Concurrent ratchet commands can reuse a message key/nonce | High | Sessions were read and rewritten without locking. Commands now hold an OS advisory lock on a persistent sidecar for the entire transaction. Tests verify competing processes fail and the lock remains effective across atomic state replacement. |
| Secret/state output follows symlinks or retains permissive mode | High | `create(true).truncate(true).mode(0600)` does not change an existing file's permissions and follows symlinks. State/output updates now use exclusive random mode-0600 temporaries, fsync, rename and directory fsync, refusing symlink or multiply hardlinked state. Identities, prekeys and new sessions refuse overwrite. Tests inspect modes and preserve pre-existing targets. |
| Replay database fails open or loses concurrent updates | Medium | Read errors were treated as an empty database; writes used a predictable `.tmp` and had no transaction lock. The store now fails on unreadable/malformed data, locks its transaction, and uses atomic private replacement. Repeated delivery exits 3 in CLI tests. |
| Invalid freshness settings silently disable the check | Medium | `--max-age` parsed with `.ok()` silently became absent on invalid input. Unknown, duplicate and missing-value flags are rejected, and malformed age values return an error. |
| One-time prekey deletion errors are ignored | High | Acceptance persisted a session, ignored deletion errors and reported consumption. Acceptance now holds a prekey lock and durably creates a consumption marker before saving the session. A crash leaving the old secret cannot reuse it while the marker remains. Deletion errors are propagated. The marker is intentionally retained. |
| Binary formats accept unauthenticated trailing bytes | Medium | Envelope, session, prekey, init and ratchet-message parsers stopped after their expected fields. They now require complete input consumption. Suite 0x02 also requires the specified 24-byte freshness metadata. This hardens parsing without changing valid wire encodings. |
| Counter overflow mutates ratchet state before failure | Medium | Send and receive chains could advance before checking counter overflow. Overflow now fails before mutation, including a test using an authenticated maximum-counter message. Invalid/duplicate skipped counters are refused during session parsing. |
| CLI input is unbounded | Medium | Whole-file/stdin reads allocated without a cap. Inputs are bounded at 32 MiB, with smaller plaintext limits accounting for envelope/base64 overhead. Library serialization rejects u32 length truncation. Normal bridge attachment uploads are separate. |
| Capturing viewed PQ messages uses the wrong cache key | Low | Org looked up the ciphertext string while the client keyed decoded text differently. It now uses the client's `(JID ID blob)` key and accepts only a string already in the display cache. Failure markers remain encrypted placeholders; capture does not decrypt on its own. |

## Dependency review

`cargo audit` queried the RustSec database at commit
`d502590ca247f3e53b56bf6c2ae40b61926800e5`, last updated 2026-09-09.
The original lockfile contained 131 dependencies and reported three vulnerability
advisories. The final lockfile contains 150 dependencies and reports **zero
vulnerability advisories**, with the one maintenance warning below. A clean
vulnerability count does not mean the dependency tree has no unknown defects.

| Advisory / issue | Original | Resolution and applicability |
|---|---|---|
| [RUSTSEC-2026-0212](https://rustsec.org/advisories/RUSTSEC-2026-0212.html) | libcrux-secrets 0.0.5 | Updated to 0.0.6 via ML-KEM 0.0.10. The advisory concerns incorrect AArch64 constant-time select/swap results; AArch64 was not tested here. |
| [RUSTSEC-2026-0207](https://rustsec.org/advisories/RUSTSEC-2026-0207.html) | libcrux-sha3 0.0.9 | Updated to 0.0.10. RustSec explicitly says the affected incremental API usage does not impact ML-KEM/ML-DSA. |
| [RUSTSEC-2026-0208](https://rustsec.org/advisories/RUSTSEC-2026-0208.html) | libcrux-sha3 0.0.9 | Updated to 0.0.10. RustSec explicitly excludes ML-KEM/ML-DSA's output-buffer lengths from the affected AVX2 use. |
| [RUSTSEC-2026-0190](https://rustsec.org/advisories/RUSTSEC-2026-0190.html) | anyhow 1.0.102, unsoundness warning | Updated to 1.0.104; no application-specific exploitability claim was made. |
| Yanked release | transitive chacha20 0.10.0 | Updated to 0.10.2. This is distinct from chacha20 0.9.1 used by the unchanged RustCrypto AEAD. |
| [RUSTSEC-2026-0173](https://rustsec.org/advisories/RUSTSEC-2026-0173.html) | proc-macro-error2 2.0.1 | **Open maintenance warning.** This remains an upstream transitive procedural-macro dependency. No patched version is identified; forcing a fork/substitution was not attempted. |

ML-KEM and ML-DSA were both upgraded from 0.0.9 to 0.0.10, retaining the same
algorithms, key lengths and protocol encodings. The updated lockfile is included
with the package manifest. Cross-version interoperability was not separately
exercised with a historical binary; roundtrip, cryptographic rejection, RFC
vectors and property tests were run against the new dependency set.

## Threat model and remaining limitations

- This custom composition is not Signal PQXDH or a Signal Double Ratchet. The
  envelope has no forward secrecy: a recipient identity-key compromise exposes
  recorded envelopes. Its intended PQ protection depends on the primitive
  assumptions, implementations, authentic key exchange and uncompromised endpoints.
- WAPQR uses an ephemeral signed bootstrap plus symmetric chains. It has no
  post-compromise recovery and no group keying. Retained skipped keys expose their
  corresponding undelivered messages if state is compromised.
- File deletion is not secure media erasure. Snapshots, journals, swap, backups,
  crash artifacts and compiler/dependency copies may retain secrets. Explicit
  owned secret buffers are zeroized; this is not a whole-process erasure guarantee.
- Store live state on a local filesystem in a mode-0700 directory owned by the
  user. Locks coordinate this revision's CLI only. Malicious directory writers,
  old binaries, filesystems with unsuitable lock/durability semantics, hardlink
  aliases, and state rollback are outside the cooperative locking model.
- Keep consumption markers and lock files. Restoring an old session or removing a
  prekey consumption marker can defeat key-reuse protection. If acceptance fails
  after marker creation, bootstrap again with a fresh prekey.
- Atomic persistence precedes output. A disk/stdout failure can lose delivery
  after state advancement; the CLI is not an atomic network transaction. Do not
  restore old chain state to recover a lost output.
- Replay/freshness policy is opt-in for envelopes, device-local, and clock-dependent.
  Replay databases need retention policy. The Emacs client still does not wire
  WAPQR session management or a durable first-accept replay store.
- Metadata (contacts, timings, sizes), transport/provider behavior, endpoint
  compromise and authentic fingerprint exchange remain outside content encryption.
- The review did not prove constant-time behavior or cryptographic composition,
  execute upstream formal verification, run Miri/sanitizers, conduct a sustained
  fuzz campaign, validate a minimum Rust toolchain, or test a live WhatsApp session.

## Adjacent files reviewed

The initial `setup.sh` created `.env` before applying mode 0600, ignored some
permission failures and built without `--locked`. The initial systemd service
expected a shell `export`-style file as `EnvironmentFile` and hardcoded
`/usr/bin/guile`, limiting Guix compatibility. These findings were forwarded to
the repository integration agent for correction and validation.

The optional Wuzapi Go patch parameterizes its SQL queries by user/message ID.
The reviewed initial version used an unbounded JSON decoder, ignored JID parse
errors and used `context.Background()` for network requests. Those findings were
forwarded for correction. It is an add-on without a standalone go.mod or the
required upstream server types; compatibility against an actual pinned Wuzapi
checkout and the media-retry event path was not executed in this component audit.
The Guix Home contrib file was source-reviewed only; no Guix Home reconfigure was
performed. Refer to the repository audit for final integration status.
